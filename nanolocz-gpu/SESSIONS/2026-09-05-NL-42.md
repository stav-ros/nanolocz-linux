## Installation Methods Documented

### Method 1: pip (development)
```bash
git clone https://github.com/stav-ros/nanolocz-linux.git
cd nanolocz-linux/nanolocz-gpu
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[test]"
```

### Method 2: pip with Napari GUI
```bash
pip install -e ".[napari]"
# PyQt6 Qt bindings included automatically
napari -w nanolocz
```

### Method 3: pip with GPU support
```bash
pip install -e ".[test,gpu]"
# Requires CUDA 12.x toolkit
```

### Method 4: Docker (CPU)
```bash
docker build -t nanolocz:cpu .
docker run --rm nanolocz:cpu nanolocz --help
```

### Method 5: Docker (GPU)
```bash
docker build -f Dockerfile.gpu -t nanolocz:gpu .
docker run --gpus all --rm nanolocz:gpu nanolocz --help
```

### Method 6: Conda (future)
```bash
conda install -c conda-forge nanolocz
# Requires conda recipe build and upload
```

## Architecture Clarification

The documentation now clearly distinguishes three layers:

1. **React Dashboard** (Web Frontend)
   - Project status & roadmap
   - CLI documentation
   - Session handoffs
   - Release readiness
   - Interactive demos
   - Does NOT execute Python code directly

2. **Napari Plugin** (Scientific GUI)
   - AFM image/movie visualization
   - Frame navigation & contrast
   - Detection overlays & tracks
   - LAFM reconstructions & 3D volumes
   - Parameter controls & export

3. **Python CLI / Core** (Execution Engine)
   - `nanolocz/cli/` (command-line tools)
   - `nanolocz/core/` (detection, tracking, leveling)
   - `nanolocz/gpu/` (LAFM, FRC, CUDA kernels)
   - `nanolocz/io/` (file I/O, format readers)
   - `nanolocz/simafm/` (simulation AFM)

**Key principle:** Both the Napari plugin and CLI call the same core Python functions, ensuring consistent results across all interfaces.
