## Deliverables Created

### 1. Core Implementation: `nanolocz/gpu/backend.py`

A comprehensive backend management module providing:

#### Enums
- **Backend**: CPU, CUDA, AUTO (auto-detection)
- **PrecisionMode**: REFERENCE (float64), MIXED (float32 GPU/float64 CPU), HIGH (float64)

#### Configuration Classes
- **BackendConfig**: Frozen dataclass with:
  - `backend`: Target backend selection
  - `precision`: Numerical precision mode
  - `device_id`: CUDA device ID
  - `memory_limit`: Optional GPU memory limit
  - `allow_downcast`: Control float32 downcasting on GPU
  - `resolve_backend()`: Auto-detect available backend
  - `get_dtype()`: Get appropriate dtype for configuration

- **TolerancePolicy**: Frozen dataclass defining numerical tolerances:
  - `rtol`: Relative tolerance
  - `atol`: Absolute tolerance
  - `name`: Human-readable identifier
  - `description`: Usage context

#### Tolerance Constants
| Constant | rtol | atol | Use Case |
|----------|------|------|----------|
| `CPU_REFERENCE_TOLERANCE` | 1e-10 | 1e-12 | Golden fixtures, reference validation |
| `CPU_STANDARD_TOLERANCE` | 1e-5 | 1e-8 | Standard CPU float64 computations |
| `GPU_FLOAT32_TOLERANCE` | 1e-3 | 1e-5 | GPU single-precision kernels |
| `GPU_FLOAT64_TOLERANCE` | 1e-7 | 1e-10 | GPU double-precision kernels |
| `CROSS_BACKEND_TOLERANCE` | 1e-4 | 1e-6 | CPU vs GPU result comparison |

#### Execution Context
- **BackendContext**: Manages array operations across backends:
  - `xp`: Array module (numpy or cupy)
  - `backend`: Resolved backend type
  - `is_gpu`: Boolean GPU indicator
  - `dtype`: Default dtype for context
  - Array creation: `zeros`, `ones`, `empty`, `allocate`, `array`
  - Data transfer: `to_cpu`, `to_backend`
  - Utilities: `copy`, `astype`, `get_stream`

#### Public Functions
- `get_tolerance(backend, precision, compare_mode)`: Select appropriate tolerance
- `assert_close(actual, expected, tolerance, label)`: Unified numerical comparison
- `validate_backend_result(result, expected_shape, expected_dtype, finite, label)`: Result validation
- `get_backend_context(backend, precision, device_id)`: Create configured context
- `create_reference_context()`: CPU float64 reference context
- `create_gpu_context(device_id, high_precision)`: GPU context (raises if CuPy unavailable)

#### Protocols
- **BackendArray**: Protocol for array-like objects
- **GPUArray**: Protocol for GPU arrays with `get()` method

## Key Design Decisions

### 1. Float64 CPU Reference Behavior
- `create_reference_context()` provides guaranteed float64 CPU execution
- Strictest tolerance (1e-10/1e-12) for golden fixture generation
- Ensures reproducible reference results independent of GPU availability

### 2. GPU Precision/Tolerance Rules
- **MIXED mode** (default): float32 on GPU for performance, float64 on CPU
- **HIGH mode**: float64 everywhere for accuracy-critical paths
- **REFERENCE mode**: Always float64 CPU for validation
- Tolerances automatically selected based on backend + precision combination

### 3. Graceful Degradation
- CuPy import failure handled gracefully with `CUPY_AVAILABLE = False`
- `create_gpu_context()` raises RuntimeError only when explicitly requested without CuPy
- AUTO backend falls back to CPU when GPU unavailable
- All tests pass in CPU-only environments (GPU tests skipped)

### 4. Backward Compatibility
- Legacy `nanolocz.gpu.utils` module preserved
- New backend API exported from `nanolocz.gpu.__init__`
- Existing code continues to work while new code uses improved API
