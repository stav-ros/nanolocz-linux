## Work Completed

### Implementation (`nanolocz/io/store.py`)

Created `NanoLoczStore` class with full CRUD operations for:

1. **Movie I/O**
   - `save_movie()` - Stores 2D/3D image arrays with metadata
   - `load_movie()` - Supports frame-range slicing for lazy loading
   - Metadata tuple→list conversion for Zarr JSON compatibility
   - Automatic overwrite handling

2. **Localizations I/O**
   - `save_localizations()` - Stores xy coordinates, frame indices, optional intensities/sigmas/score
   - `load_localizations()` - Reconstructs Localizations dataclass with frame filtering
   - Chunked storage (1000 detections/chunk) for batch efficiency

3. **Tracks I/O**
   - `save_tracks()` - Stores ParticleTrack objects in numbered subgroups
   - `load_tracks()` - Reconstructs tracks with proper empty-list handling
   - Distinguishes between "no tracks saved" (empty list) vs "tracks group missing" (KeyError)

4. **Particle Stacks I/O**
   - `save_particle_stacks()` - Stores 3D/4D particle substacks with metadata
   - `load_particle_stacks()` - Reconstructs ParticleStack dataclass
   - Validates dimensionality requirements

5. **Opener Interface**
   - `open_nanolocz()` function for unified file access
   - Format detection (.zarr, .hdf5, .tiff)
   - Proper error handling for missing/unsupported files

### Key Design Decisions

1. **Zarr v3 API**: Uses modern `compressors` parameter instead of deprecated `compressor`
2. **Schema versioning**: Stores `nanolocz_schema_version` attribute for compatibility tracking
3. **Metadata normalization**: Converts tuples to lists for JSON serialization compatibility
4. **Explicit empty state**: Tracks group stores `n_tracks` attribute to distinguish empty vs missing
5. **Chunking strategy**: 
   - Movies: chunked by frame (1, H, W)
   - Localizations: 1000 detections per chunk
   - Optimized for typical access patterns
